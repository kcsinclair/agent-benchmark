```python
"""Weighted interval scheduling in O(n log n) time.

Importing this module has no side effects. It uses only the standard library.
"""

from bisect import bisect_right


def best_schedule(jobs):
    """Return (total_weight, chosen_indices) for a maximum-weight set of
    non-overlapping jobs.

    jobs: list of (start, end, weight). Touching jobs (one ends at t, the
    next starts at t) are compatible.

    chosen_indices are indices into the input list, sorted by start time,
    with ties broken by index ascending.
    """
    n = len(jobs)
    if n == 0:
        return (0.0, [])

    # Sort job indices by end time. Start time and index only make the order
    # deterministic.
    order = sorted(range(n), key=lambda i: (jobs[i][1], jobs[i][0], i))
    ends = [jobs[i][1] for i in order]

    # dp[k] = best total weight using only the first k jobs in sorted order.
    dp = [0.0] * (n + 1)
    # prev[k] = number of jobs among the first k (sorted) whose end <= start
    # of job k.
    prev = [0] * n
    # take[k] = True if the optimum for dp[k+1] includes sorted job k.
    take = [False] * n

    for k in range(n):
        s, e, w = jobs[order[k]]
        # Every job before k with end <= s is compatible with job k. Job k
        # itself has end > s, so searching in [0, k) is enough.
        p = bisect_right(ends, s, 0, k)
        prev[k] = p
        with_k = dp[p] + float(w)
        without_k = dp[k]
        if with_k > without_k:
            dp[k + 1] = with_k
            take[k] = True
        else:
            dp[k + 1] = without_k

    # Rebuild the chosen set by walking backwards (iterative, no recursion).
    chosen = []
    k = n
    while k > 0:
        if take[k - 1]:
            chosen.append(order[k - 1])
            k = prev[k - 1]
        else:
            k -= 1

    chosen.sort(key=lambda i: (jobs[i][0], i))

    # Re-add the chosen weights in start order, so the returned total matches
    # the sum a checker would compute.
    total = 0.0
    for i in chosen:
        total += float(jobs[i][2])

    return (total, chosen)
```

**How it works**

1. **Sort by end time.** The job indices are sorted by end time, so dynamic programming can consider jobs in that order.
2. **Find the last compatible job.** For each job `k`, `bisect_right` on the sorted end times counts how many earlier jobs end at or before job `k` starts. Using `bisect_right` means a job ending exactly at the start time counts as compatible, so touching jobs are allowed. Each lookup costs O(log n).
3. **Fill the table.** `dp[k]` is the best total weight using the first `k` sorted jobs. For each job, the code keeps the better of two options: skip the job, or take it and add its weight to the best total of the compatible jobs before it. It also records whether the job was taken.
4. **Rebuild the answer.** An iterative backward walk follows the recorded choices to collect the chosen jobs. It uses no recursion, so it never hits Python's recursion limit.
5. **Order the output.** The chosen indices are sorted by `(start, index)`. The weights are then added in that order, so the reported total matches the checker's own sum.

**Complexity:** O(n log n) time for the sort and the n binary searches, and O(n) memory.

For the example, the function returns `(13.0, [2, 6])`.
