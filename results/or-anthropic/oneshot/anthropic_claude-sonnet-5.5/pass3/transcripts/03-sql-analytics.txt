Here are the four files. I haven't run them against a database.

**q1.sql**
```sql
SELECT c.name AS customer_name,
       ROUND(COALESCE(SUM(oi.quantity * p.unit_price), 0), 2) AS revenue
FROM customers c
JOIN orders o
  ON o.customer_id = c.id AND o.status = 'completed'
LEFT JOIN order_items oi ON oi.order_id = o.id
LEFT JOIN products p ON p.id = oi.product_id
GROUP BY c.id, c.name
ORDER BY revenue DESC, customer_name ASC;
```

**q2.sql**
```sql
SELECT p.name AS product_name,
       SUM(oi.quantity) AS units_sold
FROM order_items oi
JOIN orders o ON o.id = oi.order_id AND o.status = 'completed'
JOIN products p ON p.id = oi.product_id
GROUP BY p.id, p.name
ORDER BY units_sold DESC, product_name ASC
LIMIT 3;
```

**q3.sql**
```sql
SELECT c.name AS customer_name,
       c.country AS country
FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id)
ORDER BY customer_name ASC;
```

**q4.sql**
```sql
SELECT strftime('%Y-%m', o.ordered_at) AS month,
       ROUND(SUM(oi.quantity * p.unit_price), 2) AS revenue
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON p.id = oi.product_id
WHERE o.status = 'completed'
  AND strftime('%Y', o.ordered_at) = '2025'
GROUP BY strftime('%Y-%m', o.ordered_at)
HAVING SUM(oi.quantity * p.unit_price) <> 0
ORDER BY month ASC;
```

Design choices:
- **q1:** It groups by `c.id`, not just name, so two customers with the same name stay separate rows. The `LEFT JOIN`s on items and products keep a customer whose completed order has no items, with revenue 0, since the spec asks for every customer with at least one completed order.
- **q2:** Only completed orders are joined, so products with no completed sales never appear. Ties on units sold are broken by product name before the limit of 3 applies.
- **q3:** `NOT EXISTS` returns only customers with no rows in `orders` at all, whatever the status.
- **q4:** It filters to completed orders in 2025 and drops months whose revenue sums to zero.
