Here's an efficient Python 3 implementation of `scheduler.py` for the weighted interval scheduling problem:

```python
def best_schedule(jobs: list[tuple[float, float, float]]) -> tuple[float, list[int]]:
    n = len(jobs)
    if n == 0:
        return (0.0, [])

    # Sort job indices by end time, then start time, then index for stability
    order = sorted(range(n), key=lambda i: (jobs[i][1], jobs[i][0], i))

    ends = [jobs[i][1] for i in order]

    # dp[k] = best weight using first k jobs in sorted order
    dp = [0.0] * (n + 1)

    # prev[k] = index in sorted order of the last job compatible with job at sorted pos k (1-based)
    # Instead compute via binary search on the fly for each job

    import bisect

    for k in range(1, n + 1):
        idx = order[k - 1]
        s, e, w = jobs[idx]
        # Find latest job in sorted order (1-based) that ends <= s
        p = bisect.bisect_right(ends, s, 0, k - 1)
        take = w + dp[p]
        skip = dp[k - 1]
        dp[k] = take if take > skip else skip

    # Reconstruct one optimal solution
    chosen = []
    k = n
    while k > 0:
        idx = order[k - 1]
        s, e, w = jobs[idx]
        p = bisect.bisect_right(ends, s, 0, k - 1)
        take = w + dp[p]
        if take > dp[k - 1]:
            chosen.append(idx)
            k = p
        else:
            k -= 1

    # Sort chosen indices by (start, index)
    chosen.sort(key=lambda i: (jobs[i][0], i))

    return (dp[n], chosen)
```

### How it works

1. **Sorting by end time**: We sort job indices by their end time. This is crucial for the DP recurrence.

2. **Binary search for compatibility**: For each job in sorted order, we use `bisect_right` on the `ends` array to find the last job that ends at or before the current job's start time (touching is allowed since we use `<=`).

3. **DP recurrence**: 
   - `dp[k]` = best weight considering the first `k` jobs in sorted order
   - For job at position `k`, we either skip it (`dp[k-1]`) or take it plus the best result from all compatible earlier jobs (`w + dp[p]`).

4. **Backtracking**: We walk backwards from `dp[n]`, checking at each step whether taking the job was optimal. If so, we add it and jump to `p`; otherwise we move to `k-1`.

5. **Final sort**: We sort chosen indices by start time (and index for ties) as required.

### Complexity
- **Time**: O(n log n) — sorting plus n binary searches
- **Space**: O(n) for the DP array and order list
- **No recursion**, so no stack limit issues at n = 200,000

### Verification on the example

```python
jobs = [(1, 4, 5), (3, 5, 1), (0, 6, 8), (4, 7, 4), (3, 9, 6), (5, 10, 3), (6, 11, 5)]
best_schedule(jobs)  # -> (13.0, [2, 6])
```

The function correctly returns `(13.0, [2, 6])` since job 2 (0–6, weight 8) and job 6 (6–11, weight 5) touch at t=6 and are compatible.
