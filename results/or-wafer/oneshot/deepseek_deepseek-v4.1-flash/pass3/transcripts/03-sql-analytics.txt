Here are the four SQL files:

### `q1.sql`

```sql
SELECT
  c.name AS customer_name,
  ROUND(SUM(oi.quantity * p.unit_price), 2) AS revenue
FROM customers c
JOIN orders o ON o.customer_id = c.id
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON p.id = oi.product_id
WHERE o.status = 'completed'
GROUP BY c.id, c.name
ORDER BY revenue DESC, customer_name ASC;
```

### `q2.sql`

```sql
SELECT
  p.name AS product_name,
  SUM(oi.quantity) AS units_sold
FROM products p
JOIN order_items oi ON oi.product_id = p.id
JOIN orders o ON o.id = oi.order_id
WHERE o.status = 'completed'
GROUP BY p.id, p.name
ORDER BY units_sold DESC, product_name ASC
LIMIT 3;
```

### `q3.sql`

```sql
SELECT
  c.name AS customer_name,
  c.country
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL
ORDER BY customer_name ASC;
```

### `q4.sql`

```sql
SELECT
  strftime('%Y-%m', o.ordered_at) AS month,
  ROUND(SUM(oi.quantity * p.unit_price), 2) AS revenue
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON p.id = oi.product_id
WHERE o.status = 'completed'
  AND o.ordered_at >= '2025-01-01'
  AND o.ordered_at < '2026-01-01'
GROUP BY month
HAVING revenue <> 0
ORDER BY month ASC;
```

### Notes on design choices

- **q1**: Groups by `c.id` *and* `c.name` so customers sharing a name aren't merged. Uses `JOIN` (not `LEFT JOIN`) so only customers with completed orders appear. The `WHERE o.status = 'completed'` also filters out order items from non-completed orders.
- **q2**: `JOIN` through `order_items → orders` naturally excludes products with no completed sales. `GROUP BY p.id, p.name` avoids collisions between duplicate product names. `LIMIT 3` after ordering gives the top 3.
- **q3**: `LEFT JOIN ... WHERE o.id IS NULL` correctly captures customers with zero rows in `orders` regardless of status.
- **q4**: Uses a half-open date range (`>= '2025-01-01'` and `< '2026-01-01'`) rather than `LIKE '2025-%'` so it works regardless of whether `ordered_at` includes a time component. `strftime('%Y-%m', ...)` produces the required `'2025-01'` format. `HAVING revenue <> 0` drops any month whose revenue rounds to zero, per the "non-zero revenue" requirement.
