We need to implement LRU cache with TTL. Use a Map to store entries with order from most recent to least recent? In JS Map iteration order is insertion order. To implement LRU, we can move accessed/updated entries to the front (most recent). Since Map iteration order is insertion order, we can delete and re-set to move to end (most recent). But we need order from most recent to least recent for keys() output. If we treat end of Map as most recent, then keys() should return reversed order. Or we can treat front as most recent by using a doubly linked list. But requirement O(1) amortized and Map insertion order is fine. We'll treat the most recent as the newest entry (end of Map). So when we access, we delete and set again to move to end. For keys(), we need to return array from most recent to least recent, i.e., reverse of Map iteration order. So we can collect entries and reverse.

We also need to handle expiration. Each entry stores value, expiry (number). When we get/has/delete/size/keys, we need to purge expired entries. For O(1) we can check each accessed key individually. For size, we need to purge all expired entries. Could iterate over Map and delete expired entries. That's O(n) but size is O(n) anyway. Acceptable.

When set, we need to evict if capacity exceeded. Steps: compute expiry = now() + (ttlMs ?? defaultTtlMs). If ttlMs is undefined, use defaultTtlMs. If ttlMs is Infinity, expiry = Infinity. If ttlMs <=0, expiry = now() + ttlMs (which may be <= now). We'll treat as expired; we can still store but will be removed later. But spec says entry with ttlMs 0 or negative means already expired; we can just not store it. Simpler: if expiry <= now() and ttlMs not Infinity, we can just delete any existing key and return this (no insertion). But spec says set should insert or replace; if ttl already expired, then entry is considered expired and should be removed when discovered. So we can store it but it will be removed on next access. But better to not store to keep capacity. We'll treat as not storing.

When capacity exceeded: first evict expired entries. So we can iterate over Map (oldest first) and delete any expired until size <= capacity. Then if still > capacity, evict least recently used (oldest entry) i.e., first entry in Map (since we treat most recent as newest). So we delete map.entries().next().value[0].
